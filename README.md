# Million Records MySQL Performance Benchmarking System

A professional Python-based data engineering project that generates **1 million fake employee records**, inserts them into MySQL, and produces detailed performance benchmarks with visualisations.

## 🚀 Setup Steps

### 1. Create & Activate Virtual Environment

```bash
# Windows CMD
cd d:\KafkaDemo\mysql-performance-project
python -m venv venv
venv\Scripts\activate

# Windows PowerShell
python -m venv venv
.\venv\Scripts\Activate.ps1

# macOS / Linux
python3 -m venv venv
source venv/bin/activate
```

### 2. Install Dependencies

```bash
pip install -r requirements.txt
```

### 3. Set Up MySQL Database

Make sure MySQL 8.x is running, then:

```bash
mysql -u root -p < sql/setup.sql
```

Or run the SQL manually in MySQL Workbench / DBeaver.

### 4. Register the venv as a Jupyter Kernel

```bash
python -m ipykernel install --user --name=mysql-perf --display-name "MySQL Perf (venv)"
```

### 5. Open VS Code & Select Kernel

1. Open VS Code in the `mysql-performance-project/` folder
2. Open any `.ipynb` notebook
3. Click **Select Kernel** → **Jupyter Kernel** → `MySQL Perf (venv)`

---

## 🔍 Key Findings

- **Optimal batch size**: 5,000–10,000 rows per `executemany()` call
- **Bottleneck**: InnoDB redo-log flush on each `COMMIT` (mitigated by batching)
- **Scalability**: Linear O(n) insertion time — system handles 1M rows without degradation
- **UNIQUE index on email** adds ~15–20% overhead but is required for integrity

## 🛡️ Best Practices Applied

- **Bulk insertion** via `executemany()` — avoids N individual INSERT round-trips
- **Batch commits** — transaction boundary per batch, not per row
- **Indexed columns** — `email` (UNIQUE), `city`, `salary` for query performance
- **TRUNCATE before each run** — ensures clean, reproducible benchmarks
- **psutil monitoring** — real system metrics, not synthetic estimates
- **Reproducible Faker seed** — `Faker.seed(42)` for consistent data across runs
- **Modular notebooks** — each notebook has a single responsibility
